# 画质流水线：从 `scene.pkg` 到 4K 静帧

## 为什么需要这一步

Wallpaper Engine 的**场景型**壁纸在工坊目录里只暴露一个 `preview.jpg` 或 `preview.gif`，
实测 128 张里 98 张图片型的预览**全部小于 1280px**，最小 160×160。真正的画面在
`scene.pkg`（几十 MB 的专有封装）里。直接拿预览铺满 1440+ 的窗口，等于放大 8 倍，必然糊。

## 工具

- [RePKG](https://github.com/notscuffed/repkg)（MIT）：解开 `.pkg`，并把 `.tex` 转成 `.png`
- Python 3.10+ / Pillow：选层、合成、缩放

RePKG 不随仓库分发。放到 `tools/repkg/RePKG.exe`，或用 `REPKG_EXE` 指定。

## 一次解包会得到什么

以某张场景壁纸为例：

```
preview.gif        1 MB    192×192      ← 唯一的预览（糊的根源）
scene.pkg         60 MB                ← 真货
  ├─ materials/图层 1.png            3840×2160  opaque=100%   模糊背景层
  ├─ materials/亮度_对比度 1.png      3840×2160  opaque=40.8%  人物层（带 alpha）
  ├─ materials/窗帘.png              1247×2160
  └─ sounds/*.mp3
```

关键观察：**没有一张"完整画面"**，只有分层素材。所以要自己合成。

## 选层算法（still-extract.py）

1. 候选：宽 ≥ 1600 且体积 ≥ 200KB 的 png/jpg（体积门槛用来滤掉纯色遮罩）
2. 计算每张图的 alpha 覆盖率（alpha ≥ 250 的像素占比）
3. **底**：覆盖率 ≥ 99% 里面积最大的一张（同面积比体积）
4. **盖**：覆盖率在 3%–97% 之间的，按面积从大到小取最多 2 张
5. 依次 `alpha_composite`，输出 JPEG（最长边 ≤ 3840，质量 92）

覆盖率 99% 以上却选不到底的场景（只有人物层），走兜底脚本。

## 兜底合成（still-compose.py）

适用于"没有不透明背景层"的场景：

1. 取面积最大的一张（通常是带 alpha 的人物层）
2. 按 16:9 **cover 铺满**整幅
3. 透明区域用**同一张图的模糊放大版**垫底（blur 46px + 压暗 32%），而不是纯色块

这样不会出现"一张贴纸浮在模糊背景上"的廉价感：边缘由图片自身的颜色延续。

> 早期版本试过"取最小覆盖率的扣像层 + 居中放置"，结果选中了一个小装饰图标，
> 整张画面几乎全空。**按面积选最大**比按"像不像扣像"更稳。

## 比例归一（still-fit.py）

横竖比 < 1.2（竖长）或 > 2.1（超宽）的静帧，直接 cover 会裁掉太多内容。
改为：整图等比缩进 16:9 画布（占 94%），四周用同一张图的模糊版补满。主体不丢，边缘自然。

## 失败与回退

- 没有任何可用图层 → 退回 `preview.*` 做 Lanczos 放大 + UnsharpMask（能看，但不是真高清）
- 记录 `{"fail": true}`，不重复尝试；`--force` 可强制重跑
- 仍然计入轮换池，但面板会显示低清标记；"仅高清"开关可以把它们排除

## 实测数据（128 张库）

| 结果 | 数量 |
|---|---|
| 视频型（直接可用） | 28 |
| 场景型解包成功（3840×2160 或 1440p+） | 89 |
| 兜底合成成功 | 5 |
| 只有预览可放大 | 2 |
| 无 `scene.pkg`（web 型等） | 4 |

单张解包 + 合成约 5–10 秒；74 个包一轮约 6 分钟，全部在后台跑。
静帧平均 0.9 MB，整库约 83 MB。
